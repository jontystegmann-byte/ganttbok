# Blik Plan v1.8 — Drag Physics (Design Spec)

> **Source of truth** for the v1.8 drag-physics rewrite. The brainstorm that produced this spec lives in conversation memory on 2026-05-28.

## Goal

Make dragging a task bar **predictable on long bars**. Today, the bar lands "further left or right than I want" because the magnetic-snapped live preview is fractional, while the commit rounds again on `pointerup` — so the bar always jumps several pixels at release. On long bars the eye tracks the far edge, where the jump is most visible.

This release also closes two adjacent bugs that have made drag feel wrong since v1.1:

1. `CELL = 24` is hard-coded in `DragOverlay.svelte`. Cell width actually varies with the days/weeks view and any future zoom.
2. The pixel→workday conversion ignores visible weekend and holiday cells. Dragging across a weekend with weekends shown silently costs ±2 workdays per weekend crossed.

After v1.8: **what you see during drag is what commits on release**, and the day the bar lands on is the day the ghost was pointing at.

---

## Behaviour

### Drag

- The bar follows the pointer **1:1 in raw pixels** — no magnetic pull, no easing.
- A **ghost landing marker** is drawn at the workday boundary the bar will commit to if released now. The ghost ticks discretely from one workday to the next as the pointer moves; the bar itself does not tick.
- On release: the bar snaps to the ghost. The jump is predictable because the ghost has been advertising it throughout the drag.

### Ghost marker (visual)

- 1px vertical line, full row height, BP red `#E11D2A` at 40% opacity.
- 3px horizontal cap at the top and bottom so it reads as a "landing marker" rather than a grid line.
- Anchored to the **leading edge of the bar's new position** for move drags.
- Anchored to the **dragged edge** for `resize-start` / `resize-end`.
- Anchored to the **first task's leading edge** for phase drags.

### When the ghost is hidden

- Commit delta is 0 (no workday change yet) — avoids flicker on sub-cell jitter.
- Pointer is outside the timeline viewport — ghost clamps to the nearest viewport edge.

### Cursor

Unchanged. `grabbing` throughout the drag.

## Architecture

### New module: `src/lib/canvas/timeline.ts`

Small, pure, fully unit-testable. No DOM, no Svelte. Holds the calendar-aware pixel ↔ date conversion that used to be implicit in `DragOverlay.svelte`.

```ts
export interface TimelineViewport {
  startDate: Date;          // calendar date of column 0
  cellW: number;            // px per column, read from the canvas
  showWeekends: boolean;    // controls which dates have columns
  region: Region;           // ZA / US / UK / IN / CN — for holiday skip
}

// Pointer X (within the timeline) → calendar date of the column under it.
export function pxToDate(px: number, vp: TimelineViewport): Date;

// Calendar date → left-edge pixel X of its column.
export function dateToPx(date: Date, vp: TimelineViewport): number;

// Round a calendar date to the nearest workday, respecting region holidays.
// Direction: 'nearest' is the only mode used by drag; 'forward' / 'backward'
// reserved for future ripple / inbox callers.
export function snapToWorkday(
  date: Date,
  region: Region,
  dir: 'nearest' | 'forward' | 'backward',
): Date;
```

### Replace: `src/lib/snap.ts`

Deleted. Its single export (`magneticSnap`) is no longer called, and its dead `absFrac > 0.5` branch has been documented in the spec history as a latent bug rather than carried forward.

### Rewrite: `src/lib/canvas/DragOverlay.svelte`

State during drag:

```
originalStart      : Date     — bar's start at pointerdown
pointerStartDate   : Date     — date of column under pointer at pointerdown
viewport           : TimelineViewport
rawPxDelta         : number   — for the preview-bar render
ghostStart         : Date     — for the ghost marker and the commit
```

`pointermove` flow:

1. `rawPxDelta = e.clientX - dragState.startX`
2. `currentPointerDate = pxToDate(e.clientX - timelineLeft, viewport)`
3. `rawDateDelta = calendarDaysBetween(pointerStartDate, currentPointerDate)`
4. `candidateStart = addCalendarDays(originalStart, rawDateDelta)`
5. `ghostStart = snapToWorkday(candidateStart, viewport.region, 'nearest')`
6. `ghostX = dateToPx(ghostStart, viewport)`

The preview bar renders at `originalX + rawPxDelta`. The ghost renders at `ghostX`.

`pointerup` flow:

1. Compute `workdayDelta = workdaysBetween(originalStart, ghostStart, viewport.region)`.
2. If `workdayDelta === 0`, abort (no commit, no save touch).
3. Commit via the existing `ipc.dragTask({ new_start_date: ghostStart })`. The Rust side already runs the ripple — no backend changes needed.
4. `store.applyDragResult(...)` as today.

`resize-start` / `resize-end` use the same ghost machinery, with the ghost anchored to the dragged edge and the commit going through `ipc.updateTask` as today.

Phase drag computes `workdayDelta` once from the first task's leading edge, then loops through `ipc.dragTask` for each child (unchanged from today, just calendar-aware now).

### Read live cell width

`cellW` enters `DragOverlay.svelte` as a `$props()` value from `GanttCanvas.svelte`, which already owns the days/weeks/zoom state. No more `const CELL = 24`.

## Data flow

```
pointerdown
  └─► DragOverlay records originalStart, pointerStartDate, viewport, rawPxDelta=0

pointermove (per frame)
  ├─► rawPxDelta updated for the preview-bar render
  └─► ghostStart computed via timeline.ts; ghostX rendered

pointerup
  └─► if ghostStart != originalStart:
         ipc.dragTask({ new_start_date: ghostStart })
           └─► Rust ripples downstream/upstream per auto_shift_dependents
                 └─► store.applyDragResult repaints
```

The Rust side is unchanged — all the new logic is in `timeline.ts` and `DragOverlay.svelte`. DB schema stays at v7.

---

## Error handling

- Pointer leaves the window mid-drag (`pointerleave` on window): treat as a `pointerup` at the last known X. Same path, same commit.
- `pxToDate` clamps to `[startDate, endDate]` of the rendered viewport; never returns a date outside the timeline.
- `snapToWorkday` with no workday within ±90 days (impossible in practice but defensible): return `originalStart` and log a single console warning. The bar stays put.
- `ipc.dragTask` failure: existing error path — toast + revert. Unchanged.

## Testing

### Unit (added under `src/lib/canvas/`)

`timeline.test.ts`:

- `pxToDate` / `dateToPx` round-trip across days view, weeks view, and `cellW = 12`.
- `snapToWorkday` on a Saturday with `region: ZA` → Friday (nearest backward).
- `snapToWorkday` on a Sunday → Monday.
- `snapToWorkday` on **27 April 2026** (ZA Freedom Day) → 28 April (Monday).
- `snapToWorkday` on **27 April 2026** with `region: UK` → unchanged (not a UK holiday).
- `pxToDate` with `showWeekends: false` correctly walks past Sat/Sun.

`DragOverlay.test.ts` (using `@testing-library/svelte` patterns already in repo):

- Drag 1 cell right, weekends hidden, weeks view → commits +1 workday.
- Drag 7 cells right, weekends shown, days view → commits +5 workdays.
- Drag across ZA Freedom Day with region=ZA → holiday skipped.
- Drag with `cellW = 12` (zoomed-out weeks view) → no off-by-one.
- Ghost renders at the committed-position pixel, not the pointer pixel.
- Commit-delta = 0 hides the ghost.

### Integration

The existing `tests/` Tauri integration suite already covers `dragTask` ripple. No changes needed — v1.8 only changes the JS-side input to that command, not the command itself.

### Manual QA (Gray + JT)

- Drag a 4-week bar across a weekend in days view, weekends shown. Land it on the Wednesday after. Confirm bar's left edge sits on the Wednesday column.
- Drag a 12-week bar (the "long bar" case) by ~1 week. Confirm bar lands exactly where the ghost was at release — no visible jump on the far edge.
- Drag a phase containing 6 tasks. Confirm all children shift by the same workday delta.
