# Blik Plan v1.7 — Plan 2: Status Visualisation (OUTLINE)

> **Status:** Outline only. Flesh out into TDD-style task steps before execution (re-invoke `/make-plan` with this file as input, or expand inline).

**Goal:** Make task status visible and editable. Bar fill colour is driven by `task.status` (the four colours from the spec). A right-click context menu on bars and a status selector in TaskDetails both mutate status via `setTaskStatus`. A new `Tooltip.svelte` component shows rich hover info. The phase row goes red when any child is Late.

**Spec:** `docs/specs/2026-05-25-v1.7-interactive-task-status-design.md`

**Depends on:** Plan 1 (Foundation) — landed.

## Key task steps (to expand)

1. **Add CSS status tokens** — `app.css` `:root` block.
2. **`statusColour()` helper** — pure function in `TaskBar.svelte` script block (or a `src/lib/colour.ts` if shared).
3. **Bar fill switch** — change `fill={phase.colour}` to `fill={statusColour(task)}` (line 119 area of `TaskBar.svelte`).
4. **Status context menu on bars** — copy the `JobItem` `oncontextmenu` pattern; menu items: "Done", "On Track", "Not Started", "Late" (with coloured swatches).
5. **TaskDetails status selector** — `<select>` bound to `task.status`; on change of "Done", show a date picker with default = yesterday (or today if prev was Late).
6. **Phase-red-on-Late rollup** — in the phase-row rendering, compute `phaseHasLateChild = $derived(...)` and apply a red overlay or border. Worst-child wins; only Late triggers.
7. **Tooltip component** — `Tooltip.svelte` accepting `x`, `y`, and slot content; positioned `fixed` with z-index above `ContextMenu` (so > 101).
8. **Bar hover** — `onpointerenter` / `onpointerleave` on the bar `<g>`; tooltip shows status label, planned vs actual dates, days slipped (computed from `completion_date` vs planned end), dependent count.

## Acceptance criteria

- Right-clicking a bar opens a 4-item status menu; selecting any item updates the bar colour immediately and persists across app reload.
- Marking a task "Done" via TaskDetails defaults the completion date to yesterday; the date picker allows override.
- Hovering a bar (after 200ms delay) shows a tooltip with status + dates + dep count.
- Setting any task in a phase to "Late" paints the phase row red; clearing all Late states restores the phase appearance.
- The past-task fade overlay (v1.3) still works — past bars in non-Done states fade to 25% opacity over their status colour.
