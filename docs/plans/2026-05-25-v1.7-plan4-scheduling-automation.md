# Blik Plan v1.7 — Plan 4: Scheduling + Automation (OUTLINE)

> **Status:** Outline only. Flesh out before execution.

**Goal:** Bring the live-schedule behaviour online. Midnight tick narrows Not Started bars and extends Late bars, rippling downstream when `auto_shift_dependents` is on. 6am Morning Inbox surfaces tasks that ended yesterday but aren't marked Done. Marking "Done" on a task pulls dependents in (upstream ripple). Native push notifications fire for the 6am inbox.

## Key task steps

### Phase A: Upstream ripple
1. **Refactor `compute_ripple`** to take a `Direction` enum. Existing call sites keep working with `Direction::Downstream`.
2. **`compute_ripple_upstream`** — BFS over the reversed adjacency (successor → [predecessors]) and shift start dates BACK by `shift_workdays` (where shift is negative). Tasks whose new end-date would now overlap a no-work day are handled via `add_workdays_excluding` (negative count).
3. **`apply_ripple` extension** — accept direction; when called from `set_task_status` after a Done flip, compute the truncation delta (planned end - actual completion date in workdays) and call with `Direction::Upstream`.

### Phase B: Midnight tick
4. **`run_midnight_tick(conn, today: NaiveDate)`** — for each Late task in any job: extend `duration_workdays += 1`; if `job.auto_shift_dependents`, call `apply_ripple(conn, job_id, task_id, +1, Downstream)`. For each Not Started task whose `start_date < today`: set `start_date = today` and `duration_workdays = max(1, original_end - today)` (i.e. shrink, don't push end). Auto-flip Not Started → Late if `today > planned_end`.
5. **Idempotence** — store `last_midnight_tick_at` in `app_meta`; skip if already run today (local).
6. **Manual trigger command `tick_now`** — for tests and for the dev "what if I were a day later" button.

### Phase C: 6am Morning Inbox
7. **`run_morning_inbox(conn, today)`** — for each task with `planned_end_date = today - 1 day` AND `status != Done`: insert a `pending_patches` row whose patch contains a `MorningInboxItem` op. Skip tasks already in the inbox today (deduplicated by `(task_id, created_at::date)`).
8. **Idempotence** — `last_morning_inbox_at` in `app_meta`; gate by `today` to ensure once-per-day.
9. **Frontend polling** — `store.bootstrapScheduler()` runs `setInterval(() => ipc.tickNow(), 60_000)` and `setInterval(() => ipc.checkMorningInbox(), 60_000)`. Backend self-gates by time-of-day, so frontend doesn't need to care.
10. **InboxPanel rendering** — when an op is `MorningInboxItem`, show three buttons. "Done yesterday" → `setTaskStatus(taskId, 'done', yesterday)`. "Still going" → `setTaskStatus(taskId, 'late', null)`. "Pick date…" opens an inline date picker, then calls `setTaskStatus(taskId, 'done', picked)`. After action, mark the inbox patch as `applied`.

### Phase D: Notifications
11. **Add `tauri-plugin-notification`** to Cargo.toml + tauri.conf.json (notification permissions).
12. **Trigger on 6am inbox fill** — at the end of `run_morning_inbox`, if any items were created, emit a system notification: title "Blik Plan — Morning Inbox", body "N tasks from yesterday need attention". Click handler is best-effort (focus the app).

### Phase E: UI for `auto_shift_dependents`
13. **JobDetails toggle** — labelled "Auto-shift dependent tasks", with a one-line description: "When a task is marked Done early or Late, automatically move dependent tasks. Off for research / exploratory jobs."

## Acceptance criteria

- A task marked Late at noon today extends its bar by 1 day at midnight tonight; if `auto_shift_dependents` is ON, dependents push out by 1 day.
- A task with `start_date = 3 days ago, duration = 5 workdays`, status = Not Started, has its bar narrow to `start = today, duration ≈ 2` by tomorrow morning.
- A task that ended yesterday and is still On Track / Not Started at 6am local time generates an inbox item with three actions. Native notification fires.
- "Done yesterday" from the inbox marks status = Done with `completion_date = yesterday`; the bar truncates; dependents pull in (if `auto_shift_dependents`).
- Toggling `auto_shift_dependents` off and re-running the midnight tick: bars still extend, but dependents don't move.
- Manually firing `tick_now` from a dev hotkey advances the schedule as if a day had passed (useful for QA).

## Anti-pattern guards

- Do NOT trigger ripple if `auto_shift_dependents` is `false` — even if the user manually marks Done.
- Do NOT extend a Late bar past its dependents' max end date without warning the user (deadlock risk on tight schedules). If this gets messy, consider a "max extension" cap as a follow-up; for v1.7, just push.
- Do NOT use `chrono::Utc` for the 6am gate — must be `chrono::Local`.
- Do NOT block the UI thread on `tick_now` if it ends up rippling thousands of tasks — keep the ripple inside the existing rusqlite transaction pattern (`apply_ripple` already does this).
- Do NOT issue duplicate notifications — the daily `last_morning_inbox_at` gate is the source of truth.
- The Tokio-task approach (spawning a background loop in `lib.rs`) is OPTIONAL. The simpler frontend-`setInterval` approach is preferred for v1.7 — it matches the chaser polling pattern and avoids new concurrency surface area.
